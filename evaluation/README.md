# Evaluation

Regenerate everything with `bash evaluation/reproduce.sh` from the repository root.

| Path | Content |
|---|---|
| `results/solution_all/` | Submitted system on all 42 questions: `results.jsonl` (per question), `summary.json`, `report.md`, `config.json` |
| `results/solution_heldout/` | Submitted system on the held-out lecture only (11 questions written after tuning stopped) |
| `results/baseline_all/` | Working baseline (`configs/baseline.yaml`) on all questions |
| `results/baseline_vs_solution.md` | Paired bootstrap comparison (95% CI, p-value) |
| `results/sweep/` | Retrieval / modality ablations on the same index |
| `results/chunking/` | Slide-bounded vs fixed 30 s segments (re-ingested per config) |
| `results/redteam_defended/`, `results/redteam_undefended/` | 15 targeted injections with and without defences |
| `results/memtest.txt` | 18 learner-memory scenarios |
| `results/repeat_runs.json` | Three repeat runs: mean and standard deviation |
| `results/environment.txt` | Python, packages, ffmpeg/tesseract versions, CPU count, seeds |

Workload: `data/demo_course/` generated by `scripts/make_demo_course.py` (deterministic). Questions are in
`data/demo_course/eval.jsonl`; `split` is `dev`, `test` or `heldout`.

The pipeline is deterministic, so quality metrics have zero variance across repeats; latency varies slightly.
The bootstrap uses seed 0 and the red-team sampler seed 0.
